## Current Boundaries

- The Shipping Service `OrderPaid` consumer still hard-codes Jakarta as the origin city; the selected fulfillment model must replace it before automatic shipment creation is considered production-valid. Order items now snapshot product weight in grams and the consumer rejects missing/invalid weights instead of guessing. Checkout remains fail-closed; this consumer is not evidence of a trusted quote.
- Contract audit confirmed the backend cart routes are `GET /cart`, `POST /cart/items`, `PATCH /cart/items/:itemId`, and `DELETE /cart/items/:itemId` or `/cart/clear`; new customer hooks now match these contracts and normalize server `currentPrice` rather than stale stored cart price.
- Customer profile service exposes `/users/me` and `/users/me/addresses`; profile hooks now use the real paths and `PATCH` semantics, with a UI adapter for the existing profile view.
- The customer order hook targets `POST /orders/checkout`, but the UI does not submit orders. The Order Service now rejects direct checkout requests before side effects until a trusted server-issued quote can be validated; client-supplied shipping cost is not accepted as authority.
- Customer voucher validation accepts only a voucher code. Voucher Service obtains quantities from the authenticated user's internal Cart Service data and price/category/seller scope from current Product Service data; the browser cannot submit discount inputs. The Order Service independently revalidates and applies the voucher against its own catalog data at checkout.
